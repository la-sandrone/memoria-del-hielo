# 备份与恢复

> 对象：`memoria_del_hielo`（MariaDB 12.3.2，Windows 侧 mysqld，WSL 经 127.0.0.1:9002 访问）
> 位置约定：备份产物放 **D: 盘根目录**（`/mnt/<drive>/`）。
> 首次建立：2026-11-07（垂直分表切换之后）

---

## 一、命令（可直接复用）

```bash
export MYSQL_PWD='<config.toml 里的 database.password>'
TS=$(date +%Y%m%d_%H%M%S)
/usr/sbin/mariadb-dump \
  -h 127.0.0.1 -P 9002 -u mhi_user \
  --single-transaction --quick --routines --triggers --events \
  --no-tablespaces --default-character-set=utf8mb4 \
  --databases memoria_del_hielo \
  | zstd -3 -T0 -q -o "/mnt/<drive>/memoria_del_hielo_full_$TS.sql.zst"
```

- `--single-transaction`：InnoDB 一致快照，**dump 期间不阻塞检索**（MCP 可以照常服务）。
- `--databases`：产物自带 `CREATE DATABASE` + `USE`，恢复时是自包含的。
- `--no-tablespaces`：非 root 账号必须（否则报 PROCESS privilege）。
- `zstd -3 -T0`：多线程，比 gzip 快数倍；`-3` 是速度/压缩率的甜点。

## 二、恢复

```bash
zstd -dc /mnt/<drive>/memoria_del_hielo_full_<TS>.sql.zst \
  | /usr/sbin/mariadb -h 127.0.0.1 -P 9002 -u mhi_user
```

（产物里有 `CREATE DATABASE IF NOT EXISTS`，但**库里已有同名表时会直接冲突**；
真恢复前先确认目标库是空的，或先 `RENAME` 成 `*_pre_restore` 留退路。）

## 三、验证备份（**不做这一步等于没有备份**）

1. **压缩完整性**：`zstd -t <file>` —— 必须过。
2. **表数**：`zstd -dc <file> | grep -c '^CREATE TABLE'` —— 应等于库里的表数。
3. **尾部标记**：`zstd -dc <file> | tail -1` —— 应能看到 `-- Dump completed`（截断的 dump 没有它）。
4. **行数清单**：备份脚本同目录会留一份 `*.manifest.txt`，其中第一段就是**备份时刻每张表的 COUNT(*)**。
   恢复后逐表对一遍，不一致就是没恢复完整。
5. **抽样往返**（VECTOR 这类二进制列必做）：把某张表的一段恢复到临时库，比对 `MD5(VEC_ToText(embedding))`。

## 四、已实测的三件事（2026-11-07）

| 项 | 结论 |
|---|---|
| 客户端版本 | `mariadb-dump from 13.0.2-MariaDB, client 10.20`（WSL 自带），**可用** |
| VECTOR 列的编码 | 落成 `0x8E91533D…` **十六进制**，即 4096 字节 → 约 8 KB 文本（**2 倍膨胀**，算体积时别忘） |
| 往返是否无损 | **位级无损**：444 行样本恢复到 `mhi_init_check`，`MD5(VEC_ToText(embedding))` 逐行一致 |

⚠️ 归档里有一条历史结论：「官方明确认可的备份向量方式 + `mariadb-dump ≥ 11.7.2` 才安全」。
本次直接**实测验证**了这一点（样本往返 MD5 一致），比记版本号更硬。

## 五、体积与时间（按实测外推）

- 逻辑体积 ≈ 库内数据量；**VECTOR 列占双倍**（十六进制）。
  向量表现在 651,206 行 ⟹ 光这一列约 **5.3 GB 未压缩**。
- 压缩后大约是未压缩的 1/3 ～ 1/2.5（十六进制文本重复度高，压得动）。

## 六、保留策略（建议）

| 时机 | 保留 |
|---|---|
| 每次结构性变更（迁移/分表/改 DDL）前 | 全库一份，保留到变更观察期结束 |
| 日常 | 全库一份/周，保留 4 份 |
| 旧表清理（`split_memoria.py cleanup`）**之前** | 必须是**含旧表**的全库备份（否则回不去旧结构） |

> 2026-11-07 这次的备份**包含**已退役的 `documents_book_chunk_old_*` 与 `embedding_cache_old_*`，
> 所以「切回旧结构」也在这份备份的能力范围内。
